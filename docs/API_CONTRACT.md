## 1. POST `/api/v1/scan`
**Owner: Shubh** — the core pipeline endpoint.

### Request
`multipart/form-data`:
| Field | Type | Required | Notes |
|---|---|---|---|
| `image` | file | yes | JPEG/PNG label photo |
| `calibration_method` | string enum: `aruco` \| `known_object` \| `none` | yes | Which font-height calibration path to use |
| `known_object_size_mm` | float | only if `calibration_method=known_object` | e.g. `25.0` for a ₹10 coin's diameter |

### Response `200 OK`
```json
{
  "scan_id": "a1b2c3d4-...",
  "product_name_hint": "Sample Product",
  "timestamp": "2026-09-10T14:22:00Z",
  "detection": {
    "method": "yolo",
    "confidence": 0.91,
    "pdp_bbox": { "x_min": 40, "y_min": 30, "x_max": 560, "y_max": 420 }
  },
  "extracted_fields": [
    {
      "field_name": "mrp",
      "raw_ocr_text": "MRP Rs.199",
      "normalized_value": "199.00",
      "confidence": 0.95,
      "bbox": { "x_min": 100, "y_min": 350, "x_max": 220, "y_max": 380 }
    }
  ],
  "font_analysis": {
    "calibration_method": "aruco",
    "mm_per_pixel": 0.12,
    "fields": [
      {
        "field_name": "mrp",
        "measured_height_mm": 2.6,
        "required_height_mm": 2.5,
        "status": "PASS",
        "calibration_confidence": 0.88
      }
    ]
  },
  "placement_checks": [
    { "field_name": "mrp", "within_pdp": true, "confidence": 0.93 }
  ],
  "compliance_results": [
    {
      "rule_id": "RULE_6_MRP_PRESENT",
      "field_name": "mrp",
      "status": "PASS",
      "confidence": 0.95,
      "message": "MRP declaration detected and correctly formatted.",
      "rule_version": "LMPC-2011-v1.0"
    },
    {
      "rule_id": "RULE_6_CONSUMER_CARE_PRESENT",
      "field_name": "consumer_care",
      "status": "FAIL",
      "confidence": 0.97,
      "message": "Consumer care details not found on package.",
      "rule_version": "LMPC-2011-v1.0"
    }
  ],
  "overall_status": "REVIEW_REQUIRED",
  "rule_version": "LMPC-2011-v1.0",
  "evidence_image_url": "/static/evidence/a1b2c3d4-....jpg",
  "original_image_url": "/static/originals/a1b2c3d4-....jpg"
}
```

**`overall_status` / any `status` field is always one of:** `PASS` | `FAIL` | `REVIEW_REQUIRED`
(never a plain boolean — this is the confidence-aware compliance design, not binary compliant/non-compliant)

**Note:** `compliance_results` is computed by Aditya's rule engine, called *inside* this endpoint —
Shubh's code produces `extracted_fields` / `font_analysis` / `placement_checks`,
then hands off to `app.services.compliance.rule_engine.evaluate_compliance()`
before returning. It's one endpoint, two people's logic composed together.

## 2. GET `/api/v1/history`
**Owner: Aditya**

### Query params (all optional except pagination defaults)
| Param | Type | Default |
|---|---|---|
| `page` | int | 1 |
| `page_size` | int | 20 |
| `status` | `PASS`\|`FAIL`\|`REVIEW_REQUIRED` | none |
| `product_name` | string | none |
| `date_from` | ISO datetime | none |
| `date_to` | ISO datetime | none |

### Response `200 OK`
```json
{
  "total": 42,
  "page": 1,
  "page_size": 20,
  "results": [
    {
      "scan_id": "a1b2c3d4-...",
      "product_name_hint": "Sample Product",
      "timestamp": "2026-09-10T14:22:00Z",
      "overall_status": "PASS",
      "evidence_thumbnail_url": "/static/evidence/a1b2c3d4-...._thumb.jpg"
    }
  ]
}
```
Note: list items are the **lightweight** `ScanSummary`, not the full `ScanResult` — keeps the list endpoint fast.

## 3. GET `/api/v1/history/{scan_id}`
**Owner: Aditya**

Returns the **full** `ScanResult` — identical shape to the `/scan` response above.
`404` if `scan_id` doesn't exist.

## 4. GET `/api/v1/search?q={query}`
**Owner: Aditya**

Free-text search over `product_name_hint` and extracted field values.
Same response shape as `/history` (paginated `ScanSummary` list).

## 5. GET `/api/v1/reports/{scan_id}/pdf` | `/docx` | `/json`
**Owner: Aditya**

All three re-render the *same stored* `ScanResult` — no recomputation.
- `/pdf` and `/docx` → file download (`Content-Disposition: attachment`)
- `/json` → returns the raw stored `ScanResult` JSON

PDF/DOCX must include: the evidence image with bounding boxes, every
compliance result with its rule ID + confidence, and the rule version stamp.

## Field Status Semantics (applies everywhere)

| Status | Meaning |
|---|---|
| `PASS` | Declaration present, correctly formatted, confidence above threshold |
| `FAIL` | Declaration missing or clearly non-compliant, confidence above threshold |
| `REVIEW_REQUIRED` | Either the check itself is ambiguous, OR confidence is below the review threshold (0.75) — routed to a human, never silently guessed |

This is the "item 1" confidence-aware design — **never** collapse this to a boolean in the frontend or reports. Always show all three states.
